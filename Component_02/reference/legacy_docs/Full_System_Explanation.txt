PART 1 — THE DATASET: PTB-XL
================================================================================

NAME    : PTB-XL (Physikalisch-Technische Bundesanstalt ECG Dataset)
SOURCE  : PhysioNet — https://physionet.org/content/ptb-xl/1.0.3/
CITATION: Wagner et al. (2020). Scientific Data, 7(1), 154.

-----------------------------------------------------------------------
1.1  WHAT IS IN THE DATASET?
-----------------------------------------------------------------------

  - 21,837 clinical 12-lead ECG recordings from real patients
  - Sampling rate : 500 Hz (high resolution)
  - Duration      : 10 seconds per recording
  - Samples       : 5,000 time-steps per lead at 500 Hz
  - Leads         : I, II, III, aVR, aVL, aVF, V1, V2, V3, V4, V5, V6
  - Metadata      : age, sex, height, weight per patient
  - Labels        : 71 SCP-ECG diagnostic codes, each assigned by 2 cardiologists

  The original cardiologist reports are written in German.
  They are machine-translated to English using GoogleTranslator (de -> en)
  before being used by any NLP component.

-----------------------------------------------------------------------
1.2  THE 5 SUPERCLASSES (Label Structure)
-----------------------------------------------------------------------

  The 71 raw SCP codes are mapped to 5 high-level superclasses:

  NORM  — Normal ECG. No cardiac abnormality detected.
           ~9,500 records (~44%)

  MI    — Myocardial Infarction (heart attack).
           Includes: IMI, AMI, LMI, ASMI, ILMI, IPLMI, PMI, etc.
           ~5,100 records (~24%)

  STTC  — ST/T-wave Change. Ischaemia-level waveform changes.
           Includes: NST_, ISC_, ISCA, ISCI, STD_, INVT, NT_, etc.
           ~5,200 records (~24%)

  CD    — Conduction Disturbance. Electrical conduction problems.
           Includes: LBBB, RBBB, ILBBB, IRBBB, AVB1/2/3, WPW, etc.
           ~4,700 records (~22%)

  HYP   — Hypertrophy. Heart muscle thickening.
           Includes: LVH, RVH, LAO/LAE, RAO/RAE, SEHYP, etc.
           ~2,600 records (~12%) — least frequent class

  ENCODING:
    Each record has a binary label vector: [NORM, MI, STTC, CD, HYP]
    A record CAN have multiple 1s (multi-hot encoding).
    Example: [0, 1, 0, 1, 0] = patient has both MI and CD.

  CONFIDENCE RULE:
    Only SCP codes where BOTH cardiologists gave >= 100% confidence
    are kept. This ensures the highest label quality.

  NORM CORRECTION RULE:
    If a record has NORM=1 AND any pathological class=1 at the same time,
    the NORM label is dropped. A sick patient is not simultaneously normal.

-----------------------------------------------------------------------
1.3  DATA SPLIT
-----------------------------------------------------------------------

  PTB-XL provides a pre-stratified fold column (strat_fold 1–10).
  All recordings from one patient stay in the same fold (no data leakage).

  Training   : Folds 1–8  (~17,441 records)
  Validation : Fold 9     (~2,193 records)
  Test        : Fold 10   (~2,203 records, 1711 after label filtering)

-----------------------------------------------------------------------
1.4  CLASS IMBALANCE HANDLING
-----------------------------------------------------------------------

  HYP is rare (~12%). Without correction, the model ignores it.
  Two strategies are used:

  1. Weighted Focal Loss — per-class positive weights:
       NORM: 1.45 | MI: 4.69 | STTC: 2.78 | CD: 2.62 | HYP: 10.48
     Rare classes are penalized more when missed.

  2. WeightedRandomSampler — oversamples minority class records
     during training so each mini-batch sees a balanced distribution.

PART 2 — THE MODELS
================================================================================

-----------------------------------------------------------------------
MODEL A — ECG-ONLY RESNET CLASSIFIER (Primary / Deployed Model)
         Folder: checkpoints_ecg_only/
         File  : train_ecg_only.py
-----------------------------------------------------------------------

  PURPOSE:
    This is the model that runs inside the web interface.
    It takes only the 12-lead ECG signal and outputs 5 probabilities.
    It is fast enough for real-time inference.

  INPUT:
    Tensor shape: (1, 12, 5000)
    12 leads, 5000 time-steps each, normalized to zero mean / unit std.

  OUTPUT:
    5 sigmoid probabilities: [P_NORM, P_MI, P_STTC, P_CD, P_HYP]
    Each is between 0.0 and 1.0. Independent per class (multi-label).

  ARCHITECTURE — 1D ResNet (ECGResNet):

    ResidualBlock 1:  12  -> 64  channels, kernel=15, stride=2, dropout=0.1
    ResidualBlock 2:  64  -> 128 channels, kernel=7,  stride=2, dropout=0.1
    ResidualBlock 3:  128 -> 192 channels, kernel=5,  stride=2, dropout=0.2
    ResidualBlock 4:  256 -> 256 channels, kernel=3,  stride=2, dropout=0.2
    Global Average Pooling  -> Flatten -> (256,)
    Classifier Head:
      Linear(256->128) -> BatchNorm -> ReLU -> Dropout(0.3) -> Linear(128->5)
    Final Activation: Sigmoid (each class independently)

  WHAT IS A RESIDUALBLOCK?
    Each block contains:
      Conv1d -> BatchNorm1d -> ReLU -> Dropout -> Conv1d -> BatchNorm1d
    PLUS a skip connection that adds the input back to the output.
    If channel dimensions change, a 1x1 Conv adjusts the skip connection.
    This prevents vanishing gradients and allows deeper networks.

  TRAINING SETTINGS:
    Loss      : BCEWithLogitsLoss with per-class pos_weight
    Optimizer : AdamW (lr=1e-3, weight_decay=1e-4)
    Scheduler : CosineAnnealingWarmRestarts (T_0=10, T_mult=2)
    Epochs    : Up to 50 with early stopping (patience=10)
    Batch Size: 32

  DECISION THRESHOLDS:
    After training, optimal per-class thresholds are found by sweeping
    precision-recall curves on the validation set. These are saved and
    used at inference time to convert probabilities to binary predictions.

  PERFORMANCE (Test Set — 1711 records):
    Class    Precision   Recall    F1
    NORM     0.8249      0.9264    0.8728
    MI       0.6678      0.7052    0.6860
    STTC     0.7071      0.8575    0.7750
    CD       0.7378      0.7805    0.7586
    HYP      0.4167      0.6061    0.4938
    Macro F1 : 0.7172
    Exact Match (all 5 labels correct): 62.1%

-----------------------------------------------------------------------
MODEL B — MULTI-MODAL FUSION CLASSIFIER (Research Model)
         Folder: checkpoints/
         File  : train.py
-----------------------------------------------------------------------

  PURPOSE:
    The full research model. Fuses ECG signal + patient demographics +
    cardiologist report text. More powerful but slower than Model A.
    Used for research comparison, not for real-time inference.

  THREE ENCODERS:

  Encoder 1 — ECGEncoder (5-block 1D CNN):
    Block 1: Conv1d(12->32,  k=15) -> BN -> ReLU -> MaxPool1d(2) -> Dropout(0.1)
    Block 2: Conv1d(32->64,  k=11) -> BN -> ReLU -> MaxPool1d(2) -> Dropout(0.1)
    Block 3: Conv1d(64->128, k=7)  -> BN -> ReLU -> MaxPool1d(2) -> Dropout(0.2)
    Block 4: Conv1d(128->192, k=5) -> BN -> ReLU -> MaxPool1d(2) -> Dropout(0.2)
    Block 5: Conv1d(192->256, k=3) -> BN -> ReLU -> AdaptiveAvgPool1d(1)
    Output : (B, 256) vector

  Encoder 2 — DemographicEncoder (MLP):
    Input  : 6 features [age, sex, height, weight, height_missing, weight_missing]
    Layers : Linear(6->32) -> ReLU -> Dropout(0.3) -> Linear(32->64) -> ReLU
    Output : (B, 64) vector

  Encoder 3 — TextProjector (ClinicalBERT projection):
    Input  : 768-dim ClinicalBERT [CLS] embedding (pre-cached from prepare_data.py)
    Layers : Linear(768->128) -> LayerNorm(128) -> ReLU -> Dropout(0.3)
    Output : (B, 128) vector

  FUSION:
    Concatenate all three: [256 + 64 + 128] = (B, 448)
    Linear(448->256) -> BN -> ReLU -> Dropout(0.3)
    -> Linear(256->128) -> ReLU -> Dropout(0.3)
    -> Linear(128->5) [logits] -> Sigmoid

  TRAINING SETTINGS:
    Loss   : Focal Loss (gamma=2.0) with per-class alpha weights
    Sampler: WeightedRandomSampler (weight = max pos_weight of active classes)

  WHY CLINICALBERT?
    ClinicalBERT (emilyalsentzer/Bio_ClinicalBERT) is pre-trained on
    MIMIC-III clinical notes. It understands medical language much better
    than general BERT. The [CLS] token gives a 768-dim summary of the
    full report text, which is cached once per record to save time.

-----------------------------------------------------------------------
MODEL C — BIOBART REPORT GENERATOR
         Folder: checkpoints_report_gen/
         File  : train_report_gen.py
-----------------------------------------------------------------------

  PURPOSE:
    A biomedical language model trained to generate English clinical ECG
    reports from the ECG signal features. Used in two modes:
    - Tier 3 (Smoothed): paraphrases the template into natural prose.
    - Legacy: generates freely from signal (research/ablation only).

  BASE MODEL: GanjinZero/biobart-base (HuggingFace)
    BioBART is a biomedical variant of the BART sequence-to-sequence model.
    Pre-trained on biomedical literature (PubMed abstracts, clinical text).

  ARCHITECTURE:
    ECG Signal -> ECGBackbone (4-block 1D CNN) -> Linear(256->768)
    -> LayerNorm(768) -> GELU
    -> Injected into BioBART encoder hidden states
    -> BioBART decoder generates English text tokens (teacher-forced in training)

  TRAINING SETTINGS:
    Loss  : Cross-entropy on token sequences
    Metric: ROUGE-L vs English-translated cardiologist reports

  GENERATION SETTINGS:
    num_beams          : 4 (beam search)
    max_length         : 128 tokens (Tier 3) / 64 tokens (Legacy)
    no_repeat_ngram_size: 3

PART 3 — HOW THE SYSTEM WORKS (END-TO-END PIPELINE)
================================================================================

-----------------------------------------------------------------------
PHASE 1 — DATA PREPARATION (prepare_data.py)
-----------------------------------------------------------------------

  Run ONCE before any training.

  Step 1 : Load ptbxl_database.csv (21,837 rows)
  Step 2 : Load scp_statements.csv (SCP code -> superclass mapping)
  Step 3 : Parse scp_codes column (text dict -> Python dict per row)
  Step 4 : Filter to confidence >= 100% (both cardiologists agreed)
  Step 5 : Map surviving codes to 5 superclasses
  Step 6 : Apply NORM correction (drop NORM if pathological class present)
  Step 7 : Exclude records with no surviving label
  Step 8 : Translate German reports to English (GoogleTranslator)
  Step 9 : Assign train/val/test splits using strat_fold
  Step 10: Load 500Hz ECG signals, normalize, save as .npy files
           -> data/signals_cache/<ecg_id>.npy   shape: (5000, 12)
  Step 11: Run ClinicalBERT on each English report, save [CLS] embedding
           -> data/text_cache/<ecg_id>.npy      shape: (768,)
  Step 12: Compute per-lead mean/std -> save to data/norm_stats.json
  Step 13: Save data/train.csv, data/val.csv, data/test.csv

-----------------------------------------------------------------------
PHASE 2 — INFERENCE (What happens every time you analyze an ECG)
-----------------------------------------------------------------------

  INPUT: An ECG — either from the test set browser OR uploaded .dat/.hea file

  STEP 1 — Signal Loading and Normalization
    - Load the 12-lead signal (5000 x 12 array)
    - Subtract per-lead mean, divide by per-lead std (from norm_stats.json)
    - Reshape to tensor: (1, 12, 5000)

  STEP 2 — ResNet Classification (Model A)
    - Forward pass through ECGResNet
    - Output: 5 sigmoid probabilities [P_NORM, P_MI, P_STTC, P_CD, P_HYP]
    - Apply per-class thresholds -> binary predictions [0 or 1 per class]
    - Example output: NORM=0.12, MI=0.87, STTC=0.41, CD=0.09, HYP=0.05
                      -> MI detected (above threshold), others not detected

  STEP 3 — Grad-CAM (XAI — temporal heatmap)
    - Applied to the last ResidualBlock of ECGResNet
    - Computes which TIME REGIONS of the signal were most important
    - Output: 1D heatmap vector (same length as ECG)
    - Overlaid on the ECG waveform plot (red = high importance)

  STEP 4 — Integrated Gradients (XAI — lead importance)
    - 30 interpolation steps from zero baseline to real signal
    - Attributes importance to each of the 12 input channels (leads)
    - Output: Lead importance ranking (I, II, V1...V6 ranked by %)
    - Shows WHICH LEADS drove the model's decision

  STEP 5 — Report Generation (3-tier pipeline)
    - Tier 2 Template Engine (report_templates.py) runs first
    - Tier 3 BioBART Smoother paraphrases the template text
    - Legacy BioBART Free Generation runs from raw signal features

  STEP 6 — ECG Plot Generation
    - matplotlib draws all 12 ECG leads in standard clinical layout
    - Grad-CAM heatmap is overlaid using imshow (red regions = attended)
    - Image encoded as base64 PNG and returned in the JSON API response

  STEP 7 — Frontend Display
    - ECG image with heatmap shown in main panel
    - Probability bar chart per class (colored bars with % value)
    - Detected / Not Detected status badges per class
    - Lead importance list (ranked, with percentage contribution)
    - Report tabs: Template | Smoothed | Legacy
    - Ground-truth label comparison (test set browser mode only)

PART 4 — EXPLAINABILITY (xAI)
================================================================================

  Two complementary XAI methods are used:

-----------------------------------------------------------------------
4.1  GRAD-CAM  (Gradient-weighted Class Activation Mapping)
     Answers: WHERE in TIME did the model look?
-----------------------------------------------------------------------

  METHOD:
    1. Run a forward pass through ECGResNet for a specific target class.
    2. Capture the feature maps from the LAST ResidualBlock (richest features).
    3. Compute the gradient of the target class logit with respect to
       each channel of those feature maps.
    4. Average the gradients across the time dimension to get channel weights.
    5. Multiply each feature map channel by its weight and sum them up.
    6. Apply ReLU (keep only positive contributions).
    7. Upsample the resulting 1D map back to the original 5000-sample length.

  OUTPUT:
    A 1D heatmap vector aligned with the ECG timeline.
    HIGH values (red overlay) = time regions that strongly influenced the prediction.
    LOW values (blue/no overlay) = regions the model largely ignored.

  CLINICAL VALUE:
    A cardiologist can see exactly which part of the heartbeat cycle
    (P-wave, QRS complex, ST-segment, T-wave) the model is attending to.
    This builds trust — if the model detects MI and highlights the ST-segment,
    that matches clinical knowledge (ST elevation is a sign of MI).

  IMPLEMENTATION CLASS: GradCAM1D in app.py

-----------------------------------------------------------------------
4.2  INTEGRATED GRADIENTS
     Answers: WHICH LEADS were most important?
-----------------------------------------------------------------------

  METHOD:
    1. Define a baseline signal (all zeros — a flat line, no cardiac activity).
    2. Create 30 linearly interpolated signals between baseline and real input.
    3. Run each interpolated signal through ECGResNet.
    4. Compute gradients of the target class score at each interpolation step.
    5. Average the gradients across all 30 steps (numerical integration).
    6. Multiply by (real input - baseline) = the final attribution per input feature.
    7. Sum the absolute attributions across time within each of the 12 leads.
    8. Normalize so all 12 lead importances sum to 100%.

  OUTPUT:
    A ranked list of the 12 ECG leads with their % contribution.
    Example:
      V4: 18.3%
      V5: 15.7%
      II: 12.1%
      ...

  CLINICAL VALUE:
    Leads are not equally important for every condition.
    For MI: V1-V6 (precordial leads) are most informative.
    For HYP: limb leads (I, II, aVF) often show voltage changes.
    Integrated Gradients confirms whether the model uses the
    clinically expected leads for each diagnosis.

  IMPLEMENTATION FUNCTION: compute_lead_saliency in app.py

-----------------------------------------------------------------------
4.3  WHY TWO XAI METHODS?
-----------------------------------------------------------------------

  Grad-CAM tells you WHEN in the signal the model reacted.
  Integrated Gradients tells you WHICH LEADS the model relied on.

  Together they give a complete picture:
    "The model detected MI because it found elevated ST-segments
     in leads V3 and V4 during the 0.3–0.6 second window."

  This is exactly the information a cardiologist needs to verify
  whether the AI's reasoning is clinically sound.

PART 5 — REPORT GENERATION (3-TIER HYBRID PIPELINE)
================================================================================

  The system generates 3 versions of a clinical report for every ECG.
  Each tier has a different risk profile and use case.

-----------------------------------------------------------------------
TIER 2 — TEMPLATE ENGINE (Hallucination-Free)
         File: report_templates.py
-----------------------------------------------------------------------

  TYPE    : Pure Python deterministic system. No neural network.
  PURPOSE : Produce a grounded, clinically accurate report with ZERO
            risk of hallucination.

  HOW IT WORKS:
    INPUT : 5 sigmoid probabilities + 5 decision thresholds
    LOGIC :
      For each class, check if prob >= threshold.
      If yes, determine severity:
        HIGH   = prob >= threshold + 0.15
        MEDIUM = prob >= threshold (but < threshold + 0.15)
      Select the pre-written clinical sentence for that class+severity tier.
      Combine all triggered sentences into one paragraph.
      Append a closing statement (normal vs abnormal variant).

  EXAMPLE SENTENCES (built into report_templates.py):
    NORM  high   : "The ECG is within normal limits. Sinus rhythm is present..."
    MI    high   : "ST-segment changes consistent with myocardial infarction.
                    Urgent cardiology review is recommended."
    MI    medium : "Possible ischaemic changes noted. Clinical correlation advised."
    HYP   medium : "Borderline voltage findings present; ventricular hypertrophy
                    cannot be excluded."

  WHY IT CANNOT HALLUCINATE:
    The template only produces sentences for classes the CNN actually detected.
    The language is pre-written by a clinician, not invented by an LLM.
    No new clinical findings can appear that were not in the CNN's output.

  ROUGE-L: 0.0657 mean (expected to be low — template uses formal English
            while cardiologist references used German-derived shorthand.
            Semantic correctness is high; lexical overlap is low.)

-----------------------------------------------------------------------
TIER 3 — BIOBART SMOOTHER (Natural Language Polish)
         Model: checkpoints_report_gen/best_model.pt
-----------------------------------------------------------------------

  TYPE    : BioBART sequence-to-sequence model (fine-tuned)
  PURPOSE : Take the Tier 2 template text and rewrite it in more natural,
            flowing clinical prose — without adding any new findings.

  HOW IT WORKS:
    INPUT : The complete Tier 2 template text (NOT the raw ECG signal)
    TASK  : Constrained paraphrase — rephrase for natural flow
    GENERATION:
      Tokenize the template text using BioBART tokenizer
      Run BioBART decoder with beam search (num_beams=4, max_length=128)
      Post-process: _fix_smoothed_output() repairs truncation artifacts
                    _clean_text() removes formatting noise

  KEY SAFETY PROPERTY:
    BioBART only SEES the Tier 2 template text.
    It cannot invent new findings because the raw ECG signal is never
    passed to it. Its job is only to rephrase, not to diagnose.

  ROUGE-L: 0.0660 mean (slightly higher than Tier 2 — natural language
            closer to cardiologist prose style)

-----------------------------------------------------------------------
LEGACY — BIOBART FREE GENERATION (Research/Ablation Only)
          Model: checkpoints_report_gen/best_model.pt (same weights)
-----------------------------------------------------------------------

  TYPE    : BioBART encoder-decoder with ECG signal as encoder input
  PURPOSE : Research comparison. Shows what happens when a language model
            is allowed to generate freely from the signal.

  HOW IT WORKS:
    INPUT : Raw ECG signal
    PIPELINE:
      ECG -> ECGBackbone (4-block CNN) -> Linear(256->768) -> LayerNorm -> GELU
      Projected features injected into BioBART encoder hidden states
      BioBART decoder generates English text freely (beam search, max_length=64)

  WHY IT EXISTS:
    This is the ablation comparison for the research paper.
    It demonstrates that even fine-tuned biomedical models hallucinate
    clinical findings that are NOT in the signal, justifying why the
    Tier 2 "classifier-first, template-second" approach is safer.

  ROUGE-L: 0.4337 mean (much higher than Tier 2/3)
    NOTE: High ROUGE-L here is misleading. The Legacy model memorizes
    common report phrases and achieves lexical overlap with cardiologist
    text, BUT it also introduces hallucinated clinical findings more
    frequently. ROUGE-L measures word overlap, not clinical accuracy.

PART 7 — WHY THESE DESIGN CHOICES WERE MADE
================================================================================

  1. WHY SIGMOID AND NOT SOFTMAX?
     A patient can have MI AND HYP at the same time (multi-label).
     Softmax forces probabilities to sum to 1 (mutual exclusivity = WRONG).
     Sigmoid treats each class independently = CORRECT for multi-label.

  2. WHY FOCAL LOSS?
     Standard BCE loss is dominated by NORM (the majority class).
     Focal Loss down-weights easy examples and focuses on hard/rare cases.
     Crucial for improving HYP detection (rarest class).

  3. WHY TEMPLATE ENGINE FOR CLINICAL REPORTS?
     Free-text generation hallucinates clinical findings.
     A template that fills slots based on CNN outputs can ONLY say
     what the classifier detected — no hallucination vector possible.

  4. WHY KEEP THE LEGACY BIOBART MODEL?
     Ablation comparison for the research paper.
     Shows that even fine-tuned biomedical LLMs hallucinate in clinical ECG tasks.
     Justifies the Tier 2 approach as the safer alternative.

  5. WHY TWO XAI METHODS?
     Grad-CAM = temporal (WHEN the model reacted).
     Integrated Gradients = lead-level (WHICH LEADS the model used).
     Together: full spatial + temporal explanation per inference.

  6. WHY PRECOMPUTE CLINICALBERT EMBEDDINGS?
     ClinicalBERT forward pass is expensive per batch.
     Pre-computing once and caching as .npy reduces training time significantly.
     Text does not change between epochs, so caching is lossless.

  7. WHY CONFIDENCE >= 100% FOR LABELS?
     Lower thresholds include uncertain diagnoses, adding label noise.
     At 100%, both cardiologists fully agreed — highest quality labels.

  8. WHY PATIENT-LEVEL TRAIN/VAL/TEST SPLIT?
     If two recordings from the same patient are in both train and test,
     the model may effectively "memorize" that patient rather than learn
     generalizable features. PTB-XL's strat_fold prevents this.
